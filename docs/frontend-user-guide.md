# Experience Ledger 终端用户录入与审核说明

这套前端既提供经验查询，也提供终端用户的数据录入入口。基本录入使用文字、日期、选项即可，不要求用户编写 JSON。高级结构化字段供需要与业务系统对接的人员使用。

## 1. 进入工作空间

管理员启动前后端并为你配置凭证。打开工作台，输入分配给自己的访问凭证并连接。凭证对应你的操作身份与工作空间，不需要另外选择空间。

页面刷新或断开后需重新输入凭证。不要共享审核凭证；操作会按后端配置的身份记入审计。当前版本还没有企业账号登录和独立的普通用户/审核员权限模型，实际可执行操作由后端凭证类型决定。

## 2. 日常录入一条经验

打开「采集经验」，填写原始记录，建议说明：

- 当时的目标、场景与约束。
- 采取了什么行动、做了哪些尝试。
- 实际观察到什么结果。
- 哪些是事实，哪些只是推测或建议。

如需保留本次处理过程，勾选“同时记录一次过程”，填写标题、发生时间与摘要。来源、事件类型等信息不清楚时可以不填。

点击“保存候选”。这一步保留原始记录，**不代表已经确认经验正确或发布**。成功后可进入审核，或点击“开始新记录”继续录入。

同一次采集如遇网络中断，保留页面中的幂等键再重试，避免重复创建。不要把旧记录的幂等键用于新内容。

## 3. 补充证据

打开「证据记录」，默认选择“用户记录”和“文字记录”。选择合适的证据类型，填写证据内容、观察时间，必要时填写来源及可靠度。

例如：测试执行条件、重复次数与结果；工程师确认的具体事实；业务记录中的关键数据。保存后保留返回的“证据 ID”。审核人员可将这个 ID 与相应 Claim 关联。

需要更正时，按 ID 打开原证据，点击“准备更正”，填写修正内容和原因。系统生成替代证据并保留旧快照，不覆盖已发布版本的引用。当前不支持在页面上传 PDF、图片等二进制附件。

## 4. 审核并形成经验

具有治理权限的人员打开「候选审核」，选择记录并完成：

1. 核对原始内容，补充标题、摘要、问题、决策、行动、结果和经验结论。
2. 添加 Claim（结论），标明是直接观察、人工陈述还是推导。
3. 直接观察选择 OBSERVATION，并关联 SUPPORTS 证据。推导结论填写推导方法；Agent 推断在人工审核后仍保留 Agent 来源。
4. 确定业务生效时间，按需填写适用范围、约束和过程引用。
5. 点击“保存审核草稿”。保存成功后，再填写新经验的编号、领域和类型，点击“确认并发布”。

后台增强可能更新候选修订号。若出现修订冲突，请先导出草稿备份，再重新加载核对；不要把“刷新”理解为自动合并你的修改。

新证据需要改变已有经验时，发布方式选“创建后继版本”，填写经验 Family ID 和期望替代的当前版本 ID。已发布内容不能原地修改。

不适合发布的候选，可以按当前状态选择拒绝、重复、过期或合并；处置需要填写原因。合并只进行归档关联。

## 5. 查找并使用经验

打开「经验检索」，描述当前问题，或留空浏览已发布经验。可按领域、类型进一步筛选。

在结果中点击标题，核对结论、来源、关联证据、适用范围、约束与矛盾提醒。需要理解演进时，查看版本历史。高级时间筛选可以分别指定“业务有效时间”和“系统认知时间”。

从详情点击“记录使用”，版本 ID 会自动带入。确认是否曾被推荐、是否实际采用，保存一次使用记录。保留返回的 Usage ID。

## 6. 后续追加结果与新发现

在「使用与反馈」选择刚创建的记录，或输入已有 Usage ID 查询。选择结果类型、观察时间，填写结果说明，再追加反馈。

同一次使用可以多次追加结果。例如先填写阶段性成功，后续再填写新的失败观察。统计按反馈事件计算，不等于独立使用次数。只填写文字说明也可以；指标 JSON 与证据关联是可选项。

如果新发现需要改变经验结论，在经验详情的“新发现或改进建议”中提交演进候选，再进入审核。反馈本身不会自动成为正式新版本。

## 7. 查询操作历史

「审计日志」按目标 UUID 查看谁在何时做了什么、原因是什么。候选、版本和证据页面也提供审计入口。审计日志只读，不提供修改和删除操作。

## 常见情况

| 提示或现象 | 处理方式 |
|---|---|
| 没有任何记录 | 新空间初始为空，可以直接采集；不需要先导入演示数据 |
| 凭证无效 | 检查是否输入实际 token，且没有带 `Bearer ` 前缀；向管理员确认配置 |
| 没有治理权限 | 当前凭证不能审核、发布或撤销，请交由有权限的人员处理 |
| 候选修订冲突 | 保留草稿，重新加载，再核对并保存 |
| 当前版本链已变化 | 查看最新版本，重新决定如何整合 |
| 请求中断，结果不确定 | 先查询对应记录或审计，避免重复提交同一次非幂等写入 |
| 查不到一条旧经验 | 使用 Family ID 打开历史；旧版本可能已经被替代或撤销 |
| 使用记录查询返回 0 条 | 可能尚无反馈，也可能 ID 不存在；此查询本身不能证明 ID 有效，追加时后端会校验 |
